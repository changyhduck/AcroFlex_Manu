# AcroFlex 手冊變更同步

## 目的與範圍

本 skill 只供 AcroFlex_Manu 專案使用，存放於 `.agents/skills/`。當使用者要求同步章節綱要或圖片的更新時，依序完成：

`index.md 與圖片 → content.md → 使用手冊網頁`

這是被呼叫時執行的工作流程，不是檔案監控服務。建立此 skill 不代表已同步章節，也不自動排程執行。只有另外要求提交、推送或部署時才執行那些操作。

## 共用規範

開始同步前，完整閱讀這兩份同專案 skill：

- [草稿撰寫規範](../acroflex-manual-draft/SKILL.md)：適用於 index.md、圖片與 content.md 的事實查證、操作流程、術語、圖號和文件格式。
- [網頁製作規範](../acroflex-manual-web/SKILL.md)：適用於 content.md 轉 HTML、圖片 URL、目錄、搜尋、排版與驗證。

使用者要求本 skill 同步，已包含更新草稿及本機網頁的授權，可依序完成兩階段。共用 skill 中「另行要求才產生網頁」的條件在本次同步任務已滿足。

若共用 skill 路徑不存在，先尋找本專案同名 skill；確實缺失時，閱讀現有專案規範並依目前網站架構完成可確認的工作，回報缺失的規範，不能宣稱已套用不存在的內容。

## 確認章節與比較依據

1. 閱讀專案 README、manual/README.md、目標與父章 index.md、既有 content.md 和目前網站章節。檢查 Git 工作區及現有變更，區分使用者內容與本次同步所需修改。
2. 使用者指定章節時，只同步該範圍及直接相關的引用。要求同步所有更新時，盤點手冊綱要、素材及共用素材引用，建立受影響章節清單；不要把尚未撰寫的所有章節當成更新目標。
3. 有使用者指定的 Git 基準或明確的上次同步紀錄時，以該基準比對；另外檢查 staged、unstaged 與未追蹤檔案。沒有明確基準時，比較當前綱要、圖片、草稿和網頁的實際內容。HEAD 只能代表目前提交，不能當成上次同步完成的保證。
4. 不僅依修改時間或 git status 決定是否同步。來源更新可能已提交而工作區乾淨；已更新的草稿也可能尚未反映到網頁。盤點新增、修改、改名、刪除及同檔名替換的圖片。
5. 同一圖片被多章引用時，列出直接受影響的章節並同步相關圖文。實際素材目錄可能叫 asset 或 assets，以專案現有路徑為準。

## 判斷變更的影響

| 變更 | 同步處理 |
| --- | --- |
| 綱要新增或修改主題 | 補寫或修訂草稿對應段落，再完整轉換到網頁。 |
| 綱要調整順序 | 按新邏輯調整步驟、段落、圖片位置及圖文參照，避免漏段。 |
| 章節名稱或編號更動 | 確認來源識別一致後，同步草稿標題、網站章節識別、目錄、錨點及直接引用；跨章重新編號意圖不明時先確認。 |
| 新增圖片 | 實際檢視其內容，確認用途後放入對應段落，不把資料夾內所有新增圖片都強行插入正文。 |
| 同檔名圖片替換 | 重新檢視圖片並核對欄位、按鈕、狀態、範例值、圖說及步驟；URL 未變也要檢查圖文一致性。若文字仍正確，不為製造差異而改寫。 |
| 圖片改名或移動 | 確認是同一素材後，修正 Markdown 路徑與網站 URL，保留檔名大小寫及適用圖說。 |
| 圖片刪除 | 查明替代素材或引用用途。刪檔不等於功能被移除，不能直接刪除操作說明；必要時保留說明並標示缺圖，避免留下壞連結。 |
| 圖片只改善清晰度或遮蔽資訊 | 保留仍正確的描述，確認目前素材可閱讀且沒有被遮蔽的操作依據。 |
| 綱要刪除項目 | 比較實際語意；綱要簡化不等於取消既有內容。只有明確移除主題或內容不再適用時才移除對應段落。 |

## 同步草稿

按草稿撰寫規範實際檢視新增或修改的圖片；需要理解上下文時一併檢視相關未變動圖片。不可僅依檔名或二進位差異猜測 UI 更新。

以更新後的綱要及可確認素材修訂 content.md，保留仍有效且經使用者補充的完整內容。新增說明須有依據；來源與已審閱文字衝突、或圖片不足以支持關鍵操作時，指出衝突與待確認項目，繼續處理不受影響部分，不擅自決定產品行為。

同步數值、欄位解釋、操作順序、圖號、替代文字及交叉引用。兩層來源應採各自的相對路徑：content.md 相對於章節目錄，網頁圖片 URL 相對於網站入口。不要反向改寫使用者 index.md 或修改原圖來使其符合舊說明。

草稿有實質變更且原標記為 published 時，保留既有狀態慣例並註明需重新審閱；未有專案狀態規則時先維持原值，在交付中揭露。不能把完成同步當成已正式發佈。

## 同步網頁

完成草稿後，依網頁製作規範把最新 content.md 整合到根目錄手冊。保持完整正文，不只同步圖片或摘要。目標不存在於網站且內容足夠時，建立章節並加入正確父章目錄；仍只有骨架時回報缺口，不生成虛構操作頁面。

核對目前 assets/app.js 的章節 body、額外渲染段落與搜尋索引；避免同一供電規劃或欄位表在轉換後重複出現。更新圖片尺寸與圖說時維持可讀比例，保留目錄收折、縮排、編號凸排與章節連結。

Publish/ 若仍是用途未確認的本機副本，不自行覆寫。圖片 URL 未變時先以重新載入或無快取預覽驗證新圖，不為猜測的快取問題任意改名所有素材。

## 一致性檢查與交付

- 綱要變更已反映於草稿；草稿的完整相關段落、表格與圖說已反映於網頁。
- 圖片引用皆有效，圖號連續且參照一致，沒有誤用舊圖或遺漏同檔名替換。
- 章節名稱、編號、目錄、錨點與全文搜尋一致；檢查正文專有關鍵字能找到目標章節。
- 完成網頁規範中的語法、格式及可用的瀏覽器驗證；沒有畫面驗證時如實回報。
- 來源沒有語意差異且網頁已一致時，不製造無意義修改。重複執行同步不應新增重複章節、圖片或段落。
- 交付列出受影響章節、來源變更、草稿與網頁的同步結果、未解決的具體缺口及驗證範圍。只有兩階段均完成且沒有必要缺口，才宣稱同步完成。
