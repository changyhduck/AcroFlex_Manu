# AcroFlex 手冊章節網頁製作

## 輸入與範圍

本 skill 隨 AcroFlex_Manu 專案存放於 `.agents/skills/`，只處理本專案既有手冊網站。依使用者指定的 `content.md` 新增或更新網頁章節；未指定章節時依當前任務上下文確認目標，不能自行將所有草稿發佈。

`content.md` 是正文依據。完整保留其專業說明、操作步驟、條件、限制、數值、表格、警告、圖片、圖號與參考資料；轉換不能把詳細草稿改成摘要。內部編輯備註依下方規則排除，不視為手冊正文。`index.md` 可用於核對章節識別，不能用綱要替換草稿。正文有矛盾或關鍵缺口時，在交付說明中指出，不在網頁悄悄補造產品行為。

此處「加入網頁」指修改本機專案。只有使用者要求提交、推送或部署時才執行對應外部操作。`Publish/` 的來源與用途未明確前，更新根目錄網站，不自行覆寫這個副本。

## 先確認目前實作

讀取專案 README、`manual/README.md`、目標 `content.md`、`assets/app.js`、`assets/styles.css` 和根目錄 `index.html`，並檢查已有變更。以下是目前架構，若程式已改版，按實際實作調整：

- 根目錄 `index.html` 是手冊入口，載入 CSS 與 JavaScript。
- `assets/app.js` 的 `chapters` 陣列包含章節 `id`、`number`、`title`、`level`、`keywords`、`lead`、`body`。
- `body` 是 HTML；`renderContent()` 另行產生章節主標題與摘要。
- 目錄從 `chapters` 建立，大章節可收折；全文搜尋從章節 `body` 的頂層元素與 `h2` 分段建立索引。
- 部分舊章節在 `renderContent()` 額外插入供電或欄位說明。更新這些章節時須檢查最終畫面，避免來源轉換後出現重複段落。

## 正式手冊正文與內部編輯備註

網頁面向產品使用者，不是文件編輯工作紀錄。轉換前逐段區分「產品說明與操作限制」和「作者尚待查證或補寫的事項」。此規則同樣適用於表格儲存格、圖說、提示框、摘要與搜尋文字，不只處理文末。

- 不將「待確認」「待補充素材」「完整名稱待確認」「須由後續素材確認」「本草稿暫沿用」「依綱要撰寫」等編輯備註放入網頁正文。章節名稱衝突、index.md／title 欄位、缺少截圖、版本查證待辦等專案資訊亦不呈現。
- 混合章節如「注意事項與待確認事項」，只保留讀者需要的注意事項，標題改為「注意事項」。不能連同操作風險、權限、版本適用條件、資料完整性限制或必要驗證一併刪除。
- 以直接且可執行的語句說明功能、欄位及操作。移除描述撰寫過程的開場；減少與操作無關的「不推定」「不自行認定」「本節不提供」等防禦性敘述，但保留真正影響安全或正確判讀的限制。
- 若段落同時包含已確認說明與編輯待辦，保留已確認部分，將待辦列入交付說明；不得僅為消除「待確認」而補出統計口徑、完整欄位名稱、預設值、選單功能或設定行為。截斷表頭可以保留畫面字樣，不猜測完整名稱。
- 對未確認的細節，優先縮限為有來源支持的說明；只有已確認由其他章節涵蓋時，才引導讀者至該章節。不可把所有缺口一律改為「詳見後續章節」。
- 若缺口影響關鍵操作、資料安全或正確結果驗證，先請使用者補充，暫不輸出該操作流程；可繼續完成不受影響的內容。不能把刪除不確定性提示當成已完成事實查證。
- 本次僅產生網頁時，不擅自修改 content.md 或另建編輯待辦檔；原草稿保留作為來源。交付時簡要列出排除或改寫的編輯資訊及未解決的關鍵缺口。

具體寫法：

| 草稿中的描述 | 網頁處理 |
| --- | --- |
| 「依綱要，選取超融合主機雲可進入整體硬體管理範圍。」 | 「選取『超融合主機雲』，查看主機雲層級的硬體資訊。」保留既有事實，移除來源編寫敘述。 |
| 「CPU 使用相關百分比；統計方式與取樣時間待確認。」 | 保留「顯示 CPU 使用相關百分比。」將計算方式與取樣週期列為交付查證事項，不新增定義。 |
| 「章節名稱待統一：index.md 的主標題……」 | 不放入網頁；在交付說明中指出名稱差異。 |
| 「N/A 表示畫面未提供可判讀值；應核對 UPS 狀態。」 | 保留，這是讀者需要的資料判讀限制，不是編輯待辦。 |

不得用關鍵字批次刪除段落；「未確認」可能指使用者尚未確認操作對象，「資料不完整」可能是產品實際顯示訊息，必須依語意判斷。

## 內容轉換

1. 從 frontmatter 和主標題確認編號與名稱。識別衝突時先確認正確值。主標題由網站產生，`body` 不重複放第二個 `h1`；frontmatter 不顯示為正文。
2. 逐段轉換 Markdown，維持原順序、標題階層、條件分支與清單起始編號。`##` 用頂層 `h2`，`###` 用 `h3`；避免把整篇包在單一容器內，以免現有搜尋失去分段。
3. 表格使用 `table.feature-table`、`thead`、`tbody` 與 `th scope="col"`；有合適列標頭時使用 `scope="row"`。保留每個資料格、單位、範例與附註。
4. 提醒使用 `.callout`，命令區塊使用 `pre.command-block > code`，行內值用 `code`。跳脫 HTML 文字中的 `&`、`<`、`>`，避免命令或佔位符被誤認成 HTML。
5. 若 HTML 寫入 JavaScript 模板字串，安全處理反引號、反斜線與 `${`，避免範例命令或文字變成 JavaScript 插值。
6. 保留參考連結與讀者需要的適用版本、操作限制及資料判讀提醒。依前述規則排除內部編輯備註與純素材資料夾清單，在結果中說明省略了哪些編輯資訊。不要自行更改草稿 `status`，本機網頁完成不等同產品審閱或正式部署完成。

## 圖片與連結

- `content.md` 的相對圖片路徑以該文件目錄解析，再換成相對於網站入口的 URL。例如 `assets/screenshots/example.png` 轉為 `manual/03-acroflex-management/02-client-interface/assets/screenshots/example.png`。
- 保留檔名大小寫，對 URL 中必要字元做編碼，確認檔案存在。不能使用 `/Users/...` 等本機絕對路徑。
- 圖片使用 `figure.figure-card`、`img` 與 `figcaption`，保留替代文字、圖號及完整圖說，圖說只顯示一次。
- 操作截圖使用可用內容寬度與原始比例，必要時加入共用截圖樣式（`width: 100%; height: auto; max-height: none`）。現有 `.figure-card img` 固定高度為 205px，單用此 class 會使完整介面截圖過小；選用已有適合樣式或新增明確的截圖 class。
- 桌面和窄螢幕不裁切重要欄位、扭曲圖片或使內容超出頁面。寬表格可使用局部橫向捲動；保留清晰圖說與可讀文字。
- 相對文件連結須轉成可供網站閱讀的連結；指向其他已存在章節時使用網站支援的章節錨點，不讓讀者點進不存在的 HTML 檔案。

## 加入目錄與搜尋

- 更新既有章節時以唯一 `id` 替換對應物件；新增時放在正確父章之下，以數字階層排序，例如 3.9 後是 3.10，再到第 4 章。
- `id` 例如 `3.2`，`number` 例如 `3.2.`；`title` 不重複章節編號。`lead` 可精簡導讀，完整正文仍在 `body`。
- 保留編號凸排、名稱換行對齊、子章節縮排、大章節收折與選取狀態。第三層等目前未支援的層級須先檢查導覽是否能表達，不能只填入 `level: 3` 就宣稱支援。
- `keywords` 補入正文中的產品名稱、UI 名稱與相關同義詞；正文與表格應被自動索引。新的正文直接放入 `body`，避免透過渲染時才插入的段落使搜尋缺漏。
- 既有渲染補充與 `body` 重複時，僅在目標章節必要範圍整合，確認其搜尋與顯示一致。不要擴大改造其他章節。

## 驗證與交付

檢查轉換前後每個章節段落、操作步驟、表格資料、警告及圖說，確保沒有摘要化、漏段或重複。核對章節 `id` 唯一、圖片路徑有效與命令文字完整。

另做正文語氣檢查：網頁是否仍含內部待辦、素材不足的作者說明、綱要／草稿編寫過程或章節命名衝突？逐項依語意處理，確認排除編輯資訊後仍保留全部已確認產品內容、安全限制與必要驗證，且沒有把未確認功能改成確定事實。全文搜尋不得收錄被排除的編輯待辦。

執行可用 Node 的 `--check assets/app.js` 及 `git diff --check`。檢查依賴是否為既有環境，不為單一章節新增整套框架。

有可用瀏覽器工具時，開啟本機網站確認：

- 左側章節點選、父章收折、章節錨點和重新載入正常。
- 搜尋一個只出現在目標正文或表格的詞，結果能進入該章節與對應段落。
- 圖片可載入、尺寸足以閱讀、圖說完整，桌面與窄螢幕布局正常。
- 目標章節及相鄰章節無執行錯誤。

沒有瀏覽器工具時完成靜態檢查並明確說明未驗證的畫面與互動，不能宣稱通過視覺驗證。交付說明更新的章節、檔案、驗證結果與尚待處理的具體缺口。
