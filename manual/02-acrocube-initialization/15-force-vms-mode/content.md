# 2.15 將 AcroCube 主機強制設定成主要主機 (VMS)

本節說明如何在 AcroFlex 系統沒有任何可執行 VMS 服務的主機時，將一台非 VMS 的 AcroCube 主機強制設定為主要主機，使其執行 VMS 容器，讓 AcroFlex 系統能恢復管理功能。

VMS 主機是執行 VMS 服務的 AcroCube 超融合主機。VMS 服務負責管理整個 AcroFlex 超融合主機雲，其角色類似 VMware vCenter；但 VMS 是運行於容器中，不需要額外部署獨立實體主機或虛擬機器。

> **重要：** 「強制成為主要」是災難復原用途的操作。僅在確認整套 AcroFlex 系統沒有任何正在執行或可復原的 VMS 服務時使用。若原有 VMS 服務仍可能存在，貿然操作可能造成管理狀態不一致；請先依維護程序確認，必要時聯絡 AcroRed 技術支援。

## 主機雲設定頁面說明

在頂端功能列點選「**系統設定**」，再選擇「**主機雲設定**」頁籤，即可開啟主機雲狀態與相關處理功能。

頁面上方的「主機雲狀態」會顯示目前主機所在叢集、AcroVMS／資料庫狀態、VMS IP、DNS 連通性、系統維護模式、節點模式、節點狀態及韌體版本等資訊。執行強制操作前，應先保存並檢查這些狀態，作為判斷與後續排查的依據。

| 項目 | 說明 |
| --- | --- |
| 主機雲狀態 | 顯示目前 AcroCube 主機與主機雲的狀態資訊，例如叢集、AcroVMS、資料庫、VMS IP、DNS、維護模式、節點狀態及韌體版本。 |
| 強制成為主要 | 將目前這台非 VMS 的 AcroCube 主機強制設定為主要主機，並使其執行 VMS 容器。 |
| 一般模式 | 用於將主機設定為一般模式；本節不說明此功能。 |
| 系統維護模式 | 用於將主機設定為系統維護模式；本節不說明此功能。 |
| 系統一般模式 | 用於將系統回到一般模式；本節不說明此功能。 |
| 清空主機雲 | 用於清除主機雲相關設定；本節不說明此功能。 |
| 重新整理 | 重新讀取並顯示目前的主機雲狀態。 |

下圖範例中，主機雲狀態顯示沒有 Cluster，且 `AcroVMS : No`、`Database : No`。此類資訊可協助管理者確認目前沒有可用的 VMS／資料庫服務；實際是否適合執行強制操作，仍應依完整系統狀態與維護程序判斷。

## 前置條件

- 已以具管理權限的帳號登入 AcroCube Client。
- 已確認整套 AcroFlex 系統沒有任何執行中的 VMS 服務，且原 VMS 服務已損毀、遺失或無法復原。
- 已確認目前選取的 AcroCube 主機可正常運作，並具備執行 VMS 服務所需的網路與系統資源。
- 已記錄主機雲狀態、原有叢集與網路資訊，以及目前的故障情況。
- 已安排維護時段並通知相關管理者；強制角色切換可能影響既有管理作業。

## 強制設定為主要主機

1. 進入「系統設定」的「主機雲設定」頁面。
2. 先檢查頁面上方的「主機雲狀態」，再次確認沒有可用的 VMS 服務或可復原的主要主機。
3. 按下「**強制成為主要**」。
4. 等待系統完成設定，使目前這台 AcroCube 主機成為 VMS 主機並執行 VMS 容器。
5. 按下「**重新整理**」更新狀態資訊，確認 AcroVMS、資料庫及相關主機雲狀態已依預期變更。
6. 依維護程序重新連線至 AcroFlex 管理介面，確認系統已可管理，並記錄本次復原處理結果。

## 注意事項

- 本功能適用於沒有任何可運作 VMS 服務的復原情境，不應作為一般主機角色切換操作。
- 執行前須確認原有 VMS 服務不存在或無法復原；若無法判斷，請先停止操作並向 AcroRed 技術支援確認。
- 操作後請以「重新整理」及管理介面實際連線結果確認 VMS 服務與主機雲狀態。
- 完成復原後，應記錄操作主機、執行時間、操作前後狀態及後續處理事項，供維護與事件追蹤使用。
